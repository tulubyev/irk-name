# Фото в админке на российском VPS

## Задача

Администратор меняет главное фото, добавляет изображения в галерею и убирает их из карточки через существующий редактор. Сейчас интерфейс уже есть, но загрузка отключена: контент хранится в GitHub, а загрузчик поддерживает S3 либо локальный режим всего редактора.

## Подход

Добавить независимый выбор хранилища фотографий: `ADMIN_MEDIA_STORE=fs` и `ADMIN_MEDIA_ROOT=/data/media`. Markdown по-прежнему сохраняется в GitHub. Существующий S3-режим и локальную разработку сохранить совместимыми.

Альтернативы: вернуть S3 (потребует отдельного хранилища и изменения текущей раздачи) либо переключить весь редактор на fs (нарушит публикацию контента через GitHub). Для текущего VPS выбран независимый файловый загрузчик.

## Поведение

- Использовать существующие поля загрузки, выбора главного фото, галереи, авторства и лицензии.
- Обрабатывать изображения существующим sharp-кодом: JPEG/PNG/WebP/TIFF, три WebP-размера, имя с хэшем.
- Писать в тот же каталог `media/`, который nginx уже отдаёт через `cdn.irk.name`; админке дать запись, nginx оставить read-only.
- Разрешать только ключи фотографий внутри заданного каталога. Новые файлы публиковать целиком, без выдачи частично записанного изображения.
- При удалении фото из карточки не удалять файл с диска: сохранять возможность отката через git.
- Существующие ограничения размера, авторизация и CSRF-проверка сохраняются.
- Не менять владельца всего существующего каталога рекурсивно; подготовить права записи на сервере отдельно.

## Проверка и внедрение

Проверить выбор хранилища, запись трёх размеров, недопустимые ключи и сохранение совместимости; выполнить typecheck и сборку админки. Обновить compose, env.example и runbook. После публикации пользователь применяет серверную конфигурацию и проверяет загрузку, сохранение карточки, автодеплой и доступность фото по HTTPS.
